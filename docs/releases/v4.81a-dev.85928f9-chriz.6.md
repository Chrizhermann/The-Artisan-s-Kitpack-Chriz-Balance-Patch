# v4.81a-dev.85928f9-chriz.6

This release fixes a crash and memory corruption in the Shapeshifter's white
and greater white werewolf forms. Two of their animation files had no frames
for the five base directions, and BG2:EE 2.7.3.0 crashes or corrupts memory
when it draws such an empty cycle near a wall. The release changes new
installations only. CEBG manages its artifact pin separately; this owner
release does not update the collection recipe or any installed game.

## Changes

- **Werewolf attack 1 no longer has empty directions.** The Shapeshifter
  Overhaul custom werewolf sprite (components `5110` and `5111`) ships eight
  fur variants. Each attack has a base file for the five west-facing base
  directions (cycles 0 to 4) and an `E` file for the three east-facing ones
  (cycles 5 to 7). In two variants the base file of attack 1 was a byte for
  byte copy of the `E` file, so cycles 0 to 4 were empty:
  - `werewolf_white/C0W2A1.BAM` equalled `C0W2A1E.BAM`;
  - `werewolf_greater_white/C0W5A1.BAM` equalled `C0W5A1E.BAM`.

  Both have cycles `[0, 0, 0, 0, 0, 15, 15, 15]`. The werewolf form's overhand
  swing is attack 1, so about every second swing of a white or greater white
  werewolf facing one of those five directions drew an empty cycle. The game
  then builds the sprite's FX rectangle from uninitialized values. If a wall
  polygon is near the sprite, the wall clipping fill runs outside its surface:
  the game crashes with an access violation, or silently writes into foreign
  memory. White is one of the fur colors the Shapeshifter can choose, and in
  the lab the form item's eight fur effects left the greater white fur live,
  so this was reachable in normal play.
- **The fix.** `C0W2A1.BAM` and `C0W5A1.BAM` are now copies of the same fur's
  `C0W2A2.BAM` and `C0W5A2.BAM`. Attack 2 has the cycles
  `[16, 16, 16, 16, 16, 0, 0, 0]`, the same art and the same base layout, so
  attack 1 now has frames in cycles 0 to 4. The `E` files are unchanged.

  | File | Before (SHA-256, first 12) | After |
  |---|---|---|
  | `werewolf_white/C0W2A1.BAM` | `6437c82271d1` | `53d734982b3c` (= `C0W2A2.BAM`) |
  | `werewolf_greater_white/C0W5A1.BAM` | `851c4c47fe06` | `0ffa6a34dcbf` (= `C0W5A2.BAM`) |

  **What players see:** in those five directions, attack 1 of the white and
  the greater white werewolf now shows the same werewolf's attack 2. The three
  east directions are unchanged. The other six fur variants were not changed.
- **A test for the whole set.** `tests/test_shapeshifter_werewolf_animations.py`
  reads every BAM (plain or BAMC) in the eight `werewolf*` folders, tells base
  files from their `E` files by name, and requires frames in every base file's
  cycles 0 to 4 and in every `E` file's cycles 5 to 7. It fails on the files of
  `chriz.5` (ten empty cycles in the two files above) and passes now.
- **Existing installations** are not changed by this release, and there is no
  tail for it. An installed game keeps the two old files until its Shapeshifter
  Overhaul custom sprite component is installed again from this version, or
  the files are replaced separately.

The previously released balance, sorcerer, kit weapon, monk, shaman and
katana changes are unchanged.

## Validation and installation boundary

November 2 results, offline: the eight `werewolf*` folders hold 224 BAMs
besides the inventory icons (all BAMC). Before the change exactly those two base
files had empty cycles 0 to 4; every other base BAM of the C0W2 to C0W7, C0WG
and C0WW sets has frames there, and every `E` file has frames in cycles 5 to 7.
After the change no BAM has an empty direction cycle. The two new files hash
as listed above.

November 2 in-game check, in a disposable BG2:EE 2.7.3.0 lab with the greater
white werewolf form and forced overhand swings next to wall polygons, facing
the base directions: with the old `C0W5A1.BAM` the game crashed after 107
seconds in the wall clipping fill, with a bounds rectangle of uninitialized
values. With `C0W5A1.BAM` replaced by a copy of `C0W5A2.BAM` it ran 424
seconds with no crash; in 132 of 284 samples the current cell was `C0W5A1`,
with 16 frames per cycle and advancing frame numbers, and no sample had an
empty cycle.

Not covered: the in-game lab used the repair as a file copy into `override`,
not an install of this fork's tree. The white fur (`C0W2A1.BAM`) was checked
offline only; it has the same defect and the same repair, but no crash was
seen with it live. The
repair stays a stand-in until real attack 1 base frames exist: the engine bug
that makes an empty cycle dangerous is untouched, and other animation types
with an empty base or `E` cycle would meet it too.

No live game or save was changed for this release.
